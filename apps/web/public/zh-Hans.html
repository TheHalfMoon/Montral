工作方式

从第一次检测失败，到全部恢复，一个闭环。

每一步都在同一个产品里交接给下一步，故障期间不必在不同工具之间来回复制信息。

  1. 01

    观察

    HTTP、TCP、DNS、Ping、WebSocket、数据库、心跳和浏览器检测，按你设定的频率运行。

  2. 02

    发现

    多个地区的探针达成一致后才会告警，单条线路抖动不会把人叫醒。

  3. 03

    响应

    自动创建事件，告警按值班表和升级策略送达。

  4. 04

    恢复

    发布进展、标记恢复、保留时间线。状态页同步更新。

核心能力

监控、事件、值班和状态页，集中在一处。

监控

各类检测，从你选择的地区发起。

可以校验状态码、关键字和响应头，而不只是看端口通不通。检测可从多个地区探针发起，只有它们一致判定失败时才告警。

  • 每个监控单独设置频率和超时
  • 暂停、恢复、立即检测
  • 以 JSON 导入和导出监控

找到对的人，只通知一次。

支持轮换层与临时替班的值班表、无人确认时自动升级的策略，以及可订阅到个人日历的日历源。

  • 轮换正确处理时区和夏令时
  • 换班和休假的临时替班
  • 维护窗口暂停告警，但保留记录

常见问题

Montral 真的免费吗？

是的。Montral 社区版基于 MIT 许可开源，不做任何用量计量。你只需为运行它的服务器付费。

可以监控什么？

通过 HTTP / HTTPS 访问的网站和 API、TCP 端口、DNS 记录、Ping、WebSocket、PostgreSQL、MySQL 和 Redis、定时任务心跳、TLS 证书、域名到期，以及多步骤浏览器流程。

告警如何送达团队？

通过你接入的渠道，例如 Slack、Microsoft Teams、PagerDuty、邮件或 Webhook，并按值班表和升级策略路由。邮件和推送需要在部署中配置服务商。

AI Agent 能使用吗？

可以。Montral 内置 MCP 服务。Agent 通过 OAuth 接入，申请读或写权限，并受与其用户相同的项目范围限制。

有托管版本吗？

暂时没有。托管版本正在筹备，尚未公开提供，也未公布任何套餐或价格。目前请通过自托管使用 Montral。
