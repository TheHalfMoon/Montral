# Montral identity conversion contract

## Product name
All customer-visible surfaces, public endpoints, package metadata of active modules, build artifacts, CLI help, emails, status pages, support links, analytics IDs, app icons and page titles must use **Montral**.

## Legal and historical exemptions
Never remove original author copyright, LICENSE, NOTICE, required legal acknowledgments or provenance. Exact vendor snapshots remain unchanged to prove source integrity. Third-party vendor examples retain historical brand names ONLY in `vendor/` and `docs/SOURCES.md`.

## Active conversion required
- [ ] `apps/montral-api`: package name, runtime/service names, environment variables and routes
- [ ] `apps/montral-web`: every page, logo, title, footer, settings, emails and i18n copy
- [ ] `services/montral-probes`: worker name, bindings, scheduler identity and monitoring API
- [ ] `services/montral-hooks`: receiver endpoints, UI, storage, events and permissions
- [ ] `packages/montral-mcp`: MCP server name, tools, discovery and authorization
- [ ] `packages/montral-billing`: provider metadata, plans and subscription UI
- [ ] Documentation, integrations, fixtures, Docker images and CI
- [ ] Test active source for banned source-brand tokens while allowlisting legal references
- [ ] E2E parity and regression suite proves rebrand did not break behavior

## Status
Montral-branded repository and neutral vendor directory names are created. No claim is made that the three active donor applications have been comprehensively renamed, connected, built or launched.
