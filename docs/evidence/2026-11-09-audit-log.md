# Workspace audit log

## Gap
Owners and admins could not tell who created, changed or deleted monitors,
status pages, channels, members or API keys, or when. Nothing recorded the
system's own withdrawals of custom domains either.

## Scope
- Table `audit_event` (migration `0052_audit_log`): `id`, `organization_id`
  (FK to `organization`, cascade), `project_id` (nullable, no FK), `actor_type`
  (`user` | `api_key` | `system`), `actor_id`, `actor_label` (the user's email,
  or the API key's name, at the time), `action` (dotted lowercase, checked),
  `target_type`, `target_id`, `changes` (JSON object, at most 4 KiB, checked),
  `ip`, `created_at`. Indexes: `(organization_id, created_at DESC, id DESC)`
  for listing and keyset pagination, `(organization_id, target_type,
  target_id)` for target filters.
- Append-only in the database: trigger `montral_audit_event_guard` refuses
  every UPDATE and TRUNCATE, and every DELETE except (a) rows older than the
  transaction-local cutoff that `montral_prune_audit(interval)` sets (the
  trigger ignores a cutoff less than 30 days old, so a hand-set
  `montral.audit_prune_before` cannot erase recent history), and (b) the FK
  cascade when the workspace itself is deleted (the organization row is gone).
  This protects against application bugs and stray SQL, not against the table
  owner, who can drop the trigger.
- Retention: `AUDIT_RETENTION_DAYS` (30 to 3650, default 365). The scheduler's
  hourly housekeeping calls `repo.pruneAuditEvents(days)`, the only deletion
  path, on Node (server tick), Workers (cron) and `/internal/run-checks`.
- Recording: `audit(c, action, target, changes?)` (`apps/api/src/audit.ts`),
  called by the routes after a mutation succeeded. Routes do not hold their own
  transactions, so recording is best effort: one INSERT that looks up the
  actor's label in the same statement; a failure logs the fixed line `audit
  event could not be recorded; private diagnostics suppressed` and never
  changes the response. OAuth agents are recorded as their user, labelled
  `<email> (via OAuth agent <client id>)`. `ip` comes from the existing
  trusted client-IP logic (`clientIp`: `cf-connecting-ip` on Workers, the final
  `x-forwarded-for` hop only with `TRUST_PROXY`), null otherwise.
- Better Auth endpoints (organization plugin and API keys) are recorded from a
  Better Auth `hooks.after` middleware (`apps/api/src/audit-auth.ts`); the
  `hooks.before` middleware notes which workspace an API key belongs to before
  its row is deleted. Events are written only when the acting user is a member
  of the target workspace (a key whose metadata names another workspace cannot
  write into that workspace's log).
- Domain withdrawal by `recheckCustomDomains` is written in the same SQL
  statement as the withdrawal (CTE), actor `system`, so it is recorded exactly
  once and only when it happens.
- Read API: `GET /api/audit-events` and `GET /api/audit-events/export?format=csv|jsonl`
  (owners and admins; members 403; API keys or OAuth grants limited to some
  projects 403 because the log spans the workspace). Filters: action prefix
  (LIKE wildcards escaped), actorId, targetType, targetId, from, to; unknown
  parameters 400. Keyset pagination on `(created_at, id)` with the timestamp
  carried at microsecond precision in an opaque cursor. Every query is bound to
  the caller's workspace first. Responses are `private, no-store`,
  `no-referrer`.
- Export streams page by page (1000 rows per query), capped at 100,000 rows.
  The request's database is held open until the stream ends (or is cancelled),
  then closed (`databaseHeldUntil` in the app middleware). CSV cells starting
  with `=`, `+`, `-`, `@`, tab or carriage return get a leading apostrophe;
  cells with commas, quotes or line breaks are quoted.
- MCP: read-only tool `list_audit_events`, a thin call of the REST endpoint;
  the `mcp:read` scope (or `mcp:write`) is enforced by the middleware and the
  owner/admin rule by the route.
- UI: Workspace, Audit log (`/app/audit-log`): filters, "Load older events"
  paging, CSV and JSON Lines export links, a real `<table>` with caption and
  column headers; a member sees a notice instead. English and Chinese strings.
- Docs: `/docs/api` "Audit log" section (en + zh), MCP tool list,
  `/docs/self-host` retention note and `AUDIT_RETENTION_DAYS` rows (en + zh).

## What is recorded
| Area | Actions |
| --- | --- |
| Monitors | `monitor.create`, `monitor.update`, `monitor.delete`, `monitor.import` (count) |
| Status pages | `status_page.create`, `.update`, `.delete`, `.access.revoke`, `.share_link.create`, `.share_link.revoke`, `.domain.set`, `.domain.verify`, `.domain.remove`, `.subscriber.remove`, `.domain.withdrawn` (system) |
| Channels | `channel.create`, `channel.update`, `channel.delete` |
| Incidents | `incident.create`, `incident.update` (write-up or non-resolving update), `incident.resolve`, `incident.acknowledge` |
| Maintenance | `maintenance.create`, `maintenance.update` (end now), `maintenance.delete` (one occurrence, or a series with target type `maintenance_series`) |
| Projects / settings | `project.create`, `project.update`, `project.delete`, `project.alerting.update`, `workspace.settings.update`, `workspace.update` (rename through Better Auth) |
| Members | `member.invite`, `member.invite_cancel`, `member.role_change`, `member.remove` |
| API keys | `api_key.create`, `api_key.revoke` |
| Webhook inboxes | `hook_inbox.create`, `hook_inbox.delete`, `hook_event.delete`, `hook_event.replay` |

`changes.fields` lists the names of the fields a request set; `changes.values`
keeps values only for an allowlist of harmless settings (name, title, slug,
type, role, status, severity, visibility, theme, toggles, intervals, the custom
domain, ...), and a second check drops any value whose field name looks like a
credential or destination (`pass`, `secret`, `token`, `key`, `url`, `header`,
`body`, `config`, `email`, `target`, ...), even if it were added to the
allowlist by mistake.

## What is not recorded
- Secret values: status page passwords, API key values, share-link and inbox
  tokens or URLs, channel settings (webhook URLs, bot tokens, routing keys),
  monitor targets, headers and request bodies, incident update text, replay
  target URLs and responses, invitee and subscriber email addresses.
- `incident.delete`: Montral has no route that deletes an incident.
- Reads, sign-ins, invitation acceptance, leaving a workspace, workspace
  creation and deletion (deletion removes the workspace's log with it), failed
  attempts (only successful mutations are recorded), monitor manual checks and
  channel test messages.
- Maintenance end/skip/cancel are idempotent and report no result, so their
  events record the successful request even when nothing matched.

## Tests
- Unit (`apps/api/src/audit.test.ts`): allowlist and redaction (secret values
  never kept, credential-like names never allowed, truncation), CSV escaping
  (`= + - @ \t \r`, quoting), cursor round trip and rejection, retention
  setting bounds, workspace-bound SQL with escaped LIKE prefixes, the export
  stream (header, cap, paging, fixed failure log, single `done`), Better Auth
  event mapping (no key value, no invitee email, failed calls ignored,
  membership condition), and the MCP tool's REST call.
- PostgreSQL e2e (`apps/api/src/audit.e2e.test.ts`, skipped without
  `TEST_DATABASE_URL`, users signed up through the API): representative
  actions with actor, target and field names; an API key's own action carries
  its id and name; the channel webhook URL, page password, API key value,
  share-link token and inbox secret never appear in stored rows, the list API
  or either export; member 403 (list and both exports) until promoted, and
  invite / role change / removal recorded; API key revocation; cross-tenant
  isolation (another workspace sees nothing of these events by target, actor,
  type or action filters, export, or a foreign cursor); stable pagination
  (limit 3 pages equal the full list, no duplicates, newest first), invalid
  cursor and unknown parameter 400; UPDATE, DELETE, TRUNCATE and a forged prune
  setting refused by the trigger; retention removes only rows past the cutoff
  and refuses under 30 days; workspace deletion cascades; CSV / JSON Lines
  content, headers and formula escaping; project-limited key 403.
- `custom-domain-recheck.e2e.test.ts`: a withdrawal writes exactly one
  `status_page.domain.withdrawn` system event (after the admin's set and
  verify), without the TXT value.
- The PostgreSQL e2e suites run in GitHub CI only (no local PostgreSQL on the
  development machine).
