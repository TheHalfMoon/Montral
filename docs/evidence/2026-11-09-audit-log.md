# Workspace audit log

## Gap
Owners and admins had no record of who created, changed or deleted
monitors, status pages, channels, members or API keys, or when. The system's
own withdrawals of custom domains were not recorded either.

## Scope
- Table `audit_event` (migration `0052_audit_log`) has these columns:
  `id`, `organization_id` (FK to `organization`, cascade), `project_id`
  (nullable, no FK), `actor_type` (`user` | `api_key` | `system`),
  `actor_id`, `actor_label` (the user's email or the API key's name at the
  time), `action` (dotted lowercase, checked), `target_type`, `target_id`,
  `changes` (JSON object, at most 4 KiB, checked), `ip` and `created_at`.
  It has three indexes:
  - `(organization_id, created_at DESC, id DESC)` for listing and keyset
    pagination;
  - `(organization_id, target_type, target_id)` for target filters;
  - `created_at` for retention.
- Append-only in the database. The trigger `montral_audit_event_guard`
  refuses every UPDATE and TRUNCATE. It refuses every DELETE except in two
  cases:
  - Rows older than the transaction-local cutoff that `montral_prune_audit`
    sets. The trigger ignores a cutoff less than 30 days old, so a hand-set
    `montral.audit_prune_before` cannot erase recent history.
  - The FK cascade when the workspace itself is deleted (the organization
    row is gone).

  Both functions use schema-qualified tables (`public.organization`,
  `public.audit_event`) and pin `search_path = pg_catalog, public, pg_temp`.
  A session's temporary table named `organization` therefore cannot fake a
  deleted workspace. The trigger guards against application bugs and stray
  SQL, but not against the table owner, who can still drop it.
- Retention is `AUDIT_RETENTION_DAYS` (30 to 3650, default 365). The
  scheduler's hourly housekeeping calls `repo.pruneAuditEvents(days)` on Node
  (server tick), Workers (cron) and `/internal/run-checks`. This is the only
  deletion path. It deletes the oldest rows in bounded batches through
  `montral_prune_audit(interval, batch)`: 5,000 rows per statement and at
  most 20 statements per run. Rows left over wait for the next run.
- Recording: routes call `audit(c, action, target, changes?)`
  (`apps/api/src/audit.ts`) after a mutation succeeds. Routes do not hold
  their own transactions, so recording is best effort. It is one INSERT that
  looks up the actor's label in the same statement. On failure it logs the
  fixed line `audit event could not be recorded; private diagnostics
  suppressed` and never changes the response.
  - OAuth agents are recorded as their user, labelled
    `<email> (via OAuth agent <client id>)`.
  - `ip` comes from the existing trusted client-IP logic: `cf-connecting-ip`
    on Workers, the final `x-forwarded-for` hop only with `TRUST_PROXY`, and
    null otherwise.
- Better Auth endpoints (organization plugin and API keys) are recorded from
  hooks in `apps/api/src/audit-auth.ts`. Events are written only when the
  acting user is a member of the target workspace. For a call that ends
  membership (removing oneself, `/organization/leave`), membership is
  confirmed in the database before the call. Before-hooks also note which
  workspace an API key belongs to before its row is deleted.
- Domain withdrawal by `recheckCustomDomains` is recorded with actor
  `system`, and the domain is cut to 80 characters. The record is a separate
  best-effort statement after the withdrawal, so an audit failure can never
  fail or roll back the withdrawal.
- Read API:
  - Endpoints: `GET /api/audit-events` and
    `GET /api/audit-events/export?format=csv|jsonl`.
  - Access: owners and admins. Members get 403, and so do API keys or OAuth
    grants limited to some projects, because the log covers the whole
    workspace.
  - Filters: action prefix (LIKE wildcards escaped), actorId, targetType,
    targetId, from and to. Unknown parameters return 400.
  - Paging: keyset on `(created_at, id)`, with microsecond timestamps carried
    in an opaque cursor. Every query is bound to the caller's workspace first.
  - Headers: responses are `private, no-store` and `no-referrer`.
- Export streams page by page and is capped at 100,000 rows. The request's
  database stays open until the stream ends or is cancelled. CSV cells that
  start with `=`, `+`, `-`, `@`, tab, CR or LF, or with leading whitespace
  followed by `=`, `+`, `-` or `@`, get a leading apostrophe. Each export is
  recorded as `audit.export`, with the format and the names (not values) of
  the filters used.
- MCP has a read-only tool, `list_audit_events`, that calls the REST
  endpoint.
- UI: the page is at Workspace › Audit log (`/app/audit-log`). It has
  filters, paging, CSV and JSON Lines export, and an accessible table, with
  en + zh strings.
- Docs: a `/docs/api` "Audit log" section (en + zh), the MCP tool list, and
  a `/docs/self-host` retention note.

## What is recorded
| Area | Actions |
| --- | --- |
| Monitors | `monitor.create`, `monitor.update`, `monitor.delete`, `monitor.import` (count) |
| Status pages | `status_page.create`, `.update`, `.delete`, `.access.revoke`, `.share_link.create`, `.share_link.revoke`, `.domain.set`, `.domain.verify`, `.domain.remove`, `.subscriber.remove`, `.domain.withdrawn` (system) |
| Channels | `channel.create`, `channel.update`, `channel.delete` |
| Incidents | `incident.create`, `incident.update`, `incident.resolve`, `incident.acknowledge` |
| Maintenance | `maintenance.create`, `maintenance.update` (end now), `maintenance.delete` (one occurrence, or a series as `maintenance_series`). Each is recorded only when a window actually changed, in that window's project. |
| Projects / settings | `project.create`, `.update`, `.delete`, `.alerting.update`, `workspace.settings.update`, `workspace.update` |
| Members | `member.invite`, `member.invite_cancel`, `member.role_change`, `member.remove` (also removing oneself), `member.leave` |
| API keys | `api_key.create`, `api_key.revoke` |
| Webhook inboxes | `hook_inbox.create`, `hook_inbox.delete`, `hook_event.delete`, `hook_event.replay` |
| Audit log | `audit.export` |

`changes.fields` lists the names of the fields a request set.
`changes.values` keeps values only for an allowlist of harmless settings. A
second check also drops any value whose field name looks like a credential or
destination.

## What is not recorded
- Secret values: status page passwords, API key values, share-link and inbox
  tokens or URLs, channel settings, monitor targets, headers and bodies,
  incident update text, replay target URLs and responses, and invitee and
  subscriber email addresses.
- `incident.delete`: there is no incident delete route.
- Reads other than exports, sign-ins, invitation acceptance, workspace
  creation and deletion (deletion removes the log with it), failed attempts,
  manual checks and channel test messages.

## Tests
- Unit (`apps/api/src/audit.test.ts`):
  - the redaction allowlist;
  - CSV escaping, including leading whitespace, CR and LF;
  - the cursor and retention bounds;
  - workspace-bound SQL;
  - the export stream;
  - Better Auth event mapping, including leave and the
    confirmed-membership rule;
  - the MCP tool.
- PostgreSQL e2e (`apps/api/src/audit.e2e.test.ts`). These are skipped
  without `TEST_DATABASE_URL`, and users sign up through the API.
  - Recording:
    - representative events carry the right actor, target and field names;
    - no webhook URL, page password, API key, share-link or inbox secret
      appears in rows, API output or exports.
  - Access:
    - members get 403 until promoted;
    - invite, role change, removal, self-removal and leave are recorded, but
      an outsider's leave is not;
    - project-limited keys get 403 on the list and both exports.
  - Isolation and paging:
    - cross-tenant reads by filters, export or a foreign cursor see nothing;
    - pagination is stable.
  - Append-only trigger:
    - it refuses UPDATE, DELETE and TRUNCATE, a forged cutoff, and temporary
      `organization` / `audit_event` tables;
    - a forged cutoff just inside the 30-day floor is refused, and one just
      past it is allowed.
  - Retention:
    - only rows past the cutoff are removed, in bounded batches;
    - 29 days 23:59:59 is refused and 30 days is accepted;
    - workspace deletion cascades.
  - Other routes:
    - idempotent maintenance repeats are not recorded;
    - `audit.export` is recorded without filter values;
    - CSV and JSON Lines content and escaping are correct.
- `custom-domain-recheck.e2e.test.ts`: a withdrawal writes one
  `status_page.domain.withdrawn` system event without the TXT value.
- The PostgreSQL e2e suites run in GitHub CI only.
