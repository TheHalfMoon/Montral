# Google Chat, Mattermost, Gotify and Pushover alert channels — local qualification

**Date:** 2026-11-09. Engineering branch `engineering/montral-more-channels-20261109`, committed locally only (not pushed, no PR). No real provider account, webhook or paid service was used: every provider is a stubbed `fetch` or a loopback HTTP server.

## What changed

- `channel_type` enum gains `googlechat`, `mattermost`, `gotify`, `pushover` (migration `0047_channel_more_types.sql`, generated by drizzle-kit; `migrations.generated.ts` regenerated). The number may be renumbered by the maintainer.
- `apps/api/src/alerts.ts`: one `deliver()` case per type. All four use `postDirect()`, which is `guardedFetch(..., { follow: false })` like ntfy: the SSRF guard applies to every target, a 3xx counts as a failure, so a token header or the alert body is never sent on to a host nobody configured. Errors name the host or provider and the HTTP status only. Success is any 2xx (Pushover also requires `status: 1` in a body read capped at 64 KiB with a 10 s deadline, like Telegram/Lark). The response body is otherwise cancelled best-effort and never read. Failures go through the existing retry path (`safeDeliveryReason` → `notification provider HTTP <status>`).
  - **Google Chat:** `POST <webhook URL>` `{ "text" }`. `<` and `>` become `‹ ›`, so `<users/all>` mentions and `<url|text>` links cannot be injected. The text is capped at 4000 code points.
  - **Mattermost:** `POST <webhook URL>` `{ "text", "username": "Montral" }`. The text has its Markdown control characters escaped and is capped at 4000 characters (`teamsText`).
  - **Gotify:** `POST <server>/message` with header `X-Gotify-Key`, JSON `{ title: "Montral", message, priority }` plus `extras.client::notification.click.url` set to the incident when an absolute app URL exists. The priority is 8 for down, reminder and escalation, and 4 for a recovery or test.
  - **Pushover:** `POST https://api.pushover.net/1/messages.json` JSON `{ token, user, device?, title, message (≤1024), priority, url?, url_title? }`. The priority is 1 for down and escalation, and 0 for a recovery or test.
- `routes/channels.ts` zod schemas:
  - Google Chat must be `https://chat.googleapis.com/v1/spaces/<id>/messages` with `key` and `token`.
  - Mattermost must be http(s) `…/hooks/<id>`.
  - Gotify must be an `https://` base URL with no query, credentials or `/message`, plus a printable token.
  - Pushover takes a 30-character `[A-Za-z0-9]` token and `userKey`, plus optional comma-separated devices (`[A-Za-z0-9_-]{1,25}`).

  `urlProblem` (`target_not_allowed`) still applies to every `url`.
- `secrets.ts`: `userKey` joins the secret keys. Members see `https://host/••••••••` for URLs and `••••••••` for tokens and user keys, and saving a placeholder back keeps the stored value.
- Web:
  - The channel picker, form fields, help text and placeholders (`Alerting.tsx`), with zh strings.
  - The `Channel` type.
  - API docs, the changelog entry, SEO feature lists, the privacy page and `docs/GAP-MATRIX.md`.

## Provider formats

- Verified against the official docs on 2026-11-08:
  - [Google Chat webhooks](https://developers.google.com/workspace/chat/quickstart/webhooks) and [message formatting](https://developers.google.com/workspace/chat/format-messages)
  - [Mattermost incoming webhooks](https://docs.mattermost.com/developers/integrate/webhooks/incoming)
  - [Gotify push](https://gotify.net/docs/pushmsg) and [message extras](https://gotify.net/docs/msgextras): JSON is accepted, extras require JSON
  - [Pushover API](https://pushover.net/api)
- Assumed:
  - The Google Chat text cap: no limit is documented, so it uses the Teams value of 4000.
  - The Gotify priority bands (0 silent, 1–3, 4–7 sound, 8–10 sound and vibration). The official priority page did not load, so these come from search results describing the Android client.

- the exact JSON, headers and URL for each provider
